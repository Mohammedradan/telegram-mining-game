# تقرير إصلاحات P0 — Mining Clicker Empire (نسخة تجريبية قابلة للتشغيل)

**التاريخ:** 2026-11-09 (توقيت البيئة)
**الفرع:** `arena/66fbb0ee-telegram-mining-game`
**HEAD قبل وبعد:** `87781710ec0dd525fd6d1f30d1370553a2d7dda6` (لم يُنشأ أي التزام)
**الوضع:** إصلاحات تقنية P0 + استضافة تجريبية مجانية — **بدون** تغيير المحرّك أو الاقتصاد أو المكافآت أو تصميم اللعبة.
**الحالة بعد الجولة:** نسخة **تجريبية قابلة للتشغيل والاختبار** — وليست جاهزة للإطلاق العام.

## 0) الخلاصة في ستة أسطر

1. كان الخادم لا يعمل أصلاً في بيئة نظيفة، و**157 من 779 اختباراً** لم تُنفَّذ. الآن: **794 اختباراً، 793 ناجح، 0 فاشل، 1 متجاوَز** (اختبار PostgreSQL وحده، يحتاج قاعدة).
2. سبب تعطّل CI الحقيقي كان اعتماداً اختبارياً مفقوداً (`@napi-rs/canvas`) غير موجود في `package.json`/`package-lock.json` — أُضيف.
3. المصادقة وقناة WebSocket أُعيد تأمينهما: **لا يوجد `initData` في أي رابط**، والمصادقة في أول رسالة، مع مهلة وسقف للاتصالات غير الموثّقة ونافذة معدل للرسائل.
4. الحفظ والاستعادة **مُختبَران فعلياً**: نسخة أثناء عمل الخادم ← حذف القاعدة ← استعادة ← إعادة تشغيل ← نفس الرصيد والمستوى والهوية.
5. الاستضافة التجريبية المجانية موثّقة بحدودها وخطر انتهاء القواعد المجانية (`docs/TRIAL-FREE-HOSTING-AR.md`)، ومعه أداة نسخ احتياطي/استعادة.
6. **ما بقي منع الإطلاق العام:** التحقق الفعلي من CI وPostgreSQL (يتطلب دفعاً/CI — محظور هنا)، وقياس جهاز حقيقي، وجلسة لعب بشري، وباقي بنود P1.

## 6) تشغيل اللعبة للتجربة على تيليجرام

### 6.1 الآن — داخل هذه البيئة (بدون تيليجرام)

الخادم يعمل في مساحة العمل على المنفذ **3000** بوضع تطوير:
- `DATABASE_FILE=data/trial.db` (SQLite داخل `data/` المستبعد من Git)،
- `ALLOW_GUEST_AUTH=true`، `BOT_MODE=off` (لا بوت ⇒ لا مصادقة تيليجرام).

يمكنك فتح المعاينة واللعب والتعدين والقتال؛ التقدّم يُحفظ في قاعدة SQLite المحلية ويبقى بعد إعادة التشغيل.
**حدود هذا الوضع:** هوية اللاعب «ضيف» (لا `initData`)، فلا يُختبر مسار تيليجرام الحقيقي، ولا يجب استخدام بيانات حقيقية.

### 6.2 للتجربة الحقيقية على تيليجرام (مجاناً)

1. **BotFather:** `/newbot` ← توكن. ثم `/setmenubutton` ← ضع رابط الخدمة (HTTPS).
2. **Neon:** مشروع مجاني ← انسخ `DATABASE_URL`.
3. **Render:** New → Web Service من المستودع والفرع؛ Build `npm ci && npm run build`؛ Start `npm start`؛ Health `/health`.
4. **متغيرات:** `NODE_ENV=production`، `BOT_TOKEN`، `APP_URL=https://<svc>.onrender.com`، `DATABASE_URL`، `BOT_MODE=webhook`، `WEBHOOK_SECRET` (اختياري)، `BOT_USERNAME`.
5. **تحقق:** `/health` يعيد `db:"postgres"` و`botMode:"webhook"` ← `/start` يعيد زر «افتح اللعبة» ← افتح من تيليجرام ← العب دقيقة ← أغلق وأعد الفتح وتأكد أن الرصيد باقٍ.
6. **نسخة احتياطية:** `node scripts/trial-backup.cjs backup` يومياً (أو قبل كل اختبار جماعي)، ونزّل النسخ خارج المزوّد.

> تذكير: التجربة على Render المجاني تعني **نوم** الخدمة بعد 15 دقيقة (أول فتح ≈دقيقة) و**قاعدة تنتهي بعد 30 يوماً** إن استخدمت Render PG بدل Neon.
