# PR-11 — Weekly missions on the server

Base: `main` (`265ff9f`, merged PR #14 / PR-10).

## Why

Daily missions (PR-07) give a short daily loop, while race leaderboards already rotate on ISO weeks
(`currentWeekKey`). The roadmap's next progression layer is **weekly missions** on the server —
built on the exact same trust boundary as daily missions: deterministic per-player/per-week
generation, progress updated exclusively inside `applyOps` from verified operations, and sequenced
claiming recorded in `op_ledger`.

## Rules

* Every ISO week (`currentWeekKey(new Date(now))`, e.g. `2026-W42`, resetting Monday `00:00` UTC)
  each player gets **3 distinct weekly missions** chosen deterministically from `WEEKLY_MISSION_POOL`
  with `xorshift(hash32("weekly:userId:week"))` — same player + same ISO week ⇒ same set on every
  device/server.
* Pool (target · reward):

  | key | counts | target | gold | xp | mode |
  |---|---|---|---|---|---|
  | `mine_energy` | energy actually spent by accepted clicks | 3,000 | 500 | 120 | `sum` |
  | `mine_gold` | gold minted by accepted clicks | 4,000 | 500 | 120 | `sum` |
  | `runs` | accepted adventure runs | 15 | 600 | 150 | `sum` |
  | `gems` | gems in accepted runs (after the physics clamp) | 300 | 600 | 150 | `sum` |
  | `score` | best single accepted run (max) | 650 | 700 | 180 | `max` |
  | `boss` | real boss kills (mode boss, ≥ 8 s) | 3 | 900 | 220 | `sum` |
  | `boost` | boost activations | 8 | 400 | 100 | `sum` |
  | `buy` | successful `buy` / `buy_adv` | 6 | 500 | 120 | `sum` |
  | `play_time` | accepted run seconds | 900 | 600 | 150 | `sum` |
  | `survival` | best survival-mode score (max) | 400 | 700 | 180 | `max` |
  | `arena` | paid verified arena wins | 8 | 500 | 120 | `sum` |

* Progress is only ever increased inside `applyOps` via `trackMission`, after the op has been
  accepted and clamped — rejected or unpaid (`too_soon`) ops contribute nothing. A claimed weekly
  mission stops counting.
* Claiming is a sequenced op `{ type: 'weekly_mission', key }` (idempotent per session/seq like
  every other op); the server pays gold + XP, increments `sync.weeklyClaimed`, writes an
  `op_ledger` row (`kind: 'weekly_mission'`, detail `{ key, week, xp }`) and answers
  `ok { gold, xp, week }` or `rejected { reason: incomplete | claimed }` / `invalid` (not one of
  this week's keys). `key: 'bonus'` claims the all-three weekly bonus (1,000 🪙 + 300 XP) once
  every weekly mission is claimed.
* Storage: `sync_json.weeklyMissions = { week, items: [{ key, progress, claimed }], bonusClaimed }`
  and `sync_json.weeklyClaimed` — initialized in both `freshSync` and `ensureSync` (no schema
  change, no balance reset). On a new ISO week, or a missing/corrupt record on legacy rows,
  `ensureWeeklyMissions` deals the current week's set.

## API

`/api/me`, `/api/ops` and `/api/claim-daily` now include:

```json
"weeklyMissions": {
  "week": "2026-W42", "resetsIn": 354500,
  "items": [{ "key": "buy", "icon": "🛒", "title": "اشترِ 6 ترقيات هذا الأسبوع",
              "target": 6, "progress": 2, "done": false, "claimed": false, "gold": 500, "xp": 120 }],
  "bonus": { "gold": 1000, "xp": 300, "ready": false, "claimed": false }
}
```

## Client (`public/index.html`, identity preserved)

* Collapsible `🗓️ مهام الأسبوع` card (`#weekly-missions-box`) on the play tab right under the daily
  missions card: week label + reset countdown, one row per weekly mission (progress bar, reward,
  claim button enabled only when `done`), and the all-three weekly bonus row.
* `claimWeeklyMission(key)` is optimistic like `claimMission(key)`: gold shows immediately, the row
  locks, `{ type: 'weekly_mission', key, expected }` is queued, and the next sync adopts the
  server's answer (a rejected claim is not re-applied, reverting the optimistic gold). The sync
  line announces `🗓️ مهمة أسبوعية مكتملة: +500 🪙 +120 خبرة` (or `مكافأة إكمال مهام الأسبوع`).

## Tests

* `test/economy.test.js` (+4): deterministic 3-mission weekly deal with Arabic titles and ISO week
  key; progress from verified ops only (rejected boosts/purchases ignored, `buy` 6/6 paid once,
  second claim ⇒ `claimed`, ledger row `weekly_mission`, `weeklyClaimed` counter, weekly bonus
  1,000 gold + 300 XP only after all three); adventure runs and verified arena wins feed weekly
  counters while `too_soon` arena wins do not; ISO week rollover, legacy row without
  `weeklyMissions`, and corrupt records all heal without touching balances.
* `test/client-sync.test.js` (+1, updated id guard): weekly missions adopted into `profile`,
  optimistic claim re-applied over an older server state and announced once confirmed, rejected
  claim reverts; `#weekly-missions-box`, `#weekly-missions-list`, `#weekly-missions-reset` verified
  in markup.
* `test/page-boot.test.js` (+1): the weekly missions card renders progress/claimable/claimed/bonus
  rows and a click queues one `weekly_mission` op with optimistic gold.
