# Reject untrusted cloud migration

Base: `main` at `2a7304d3e705425ec5b680906951cde6f3fc2d09`.

## Problem
`migrate: true` bypassed all anti-cheat checks during the initial save window. A client could import arbitrary gold, lifetime earnings and upgrades; the purported one-time condition did not persist a consumed flag.

## Changes
- Remove the baseline trust bypass for every client, including new users.
- Keep the offline save as `mining_offline_backup` rather than importing unverified currency.
- Reject missing/non-object save state with HTTP 400.
- Retain existing cloud accounts and trusted server-file migration.
- Replace insecure migration test funding with actual server referral rewards.

## Validation actually run
Node.js v22.23.3, `npm ci`, `npm run build`, `npm test`: **24/24 passed** (baseline: 20/20).
New regressions cover repeated migration attempts, existing accounts, malformed states, and offline backup behavior. No Telegram/mobile manual QA performed.

## Limits
This closes a specific bypass; it does not convert the existing bounded client-save economy into an authoritative action protocol. CI for this branch has not run because GitHub write access is unavailable. Do not merge before remote CI passes.
