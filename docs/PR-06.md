# PR-06 — Experience points and level on the server

Base: PR-05 (verified adventure runs). Same branch, separate commit.

## Why

Level was `floor(totalEarned / 5000) + 1` on both sides — a function of gold, which the server now
controls, but it rewarded only earning and inflated quickly late-game (passive income alone levels
you). The roadmap item was "XP": a progression signal that reflects verified *activity* across the
whole game, computed where it cannot be forged, and that can later gate missions/achievements.

## Rules (server only — `state.xp` is never accepted from the client)

| Verified event | XP |
|---|---|
| Mining | 1 per 10 energy actually spent (accepted clicks × click power); the remainder is carried in `sync.xpCarry`, so short batches lose nothing |
| Upgrade purchase (`buy`, `buy_adv`) | `floor(cost / 20)` — only when the purchase succeeds |
| Boost activation | 10 |
| Adventure run (`run`, accepted) | `floor(duration / 4) + floor(gems / 2)` + 25 for a real boss kill (race rounds included) |
| Arena win (`reward`, paid) | 10 |
| Daily reward | `min(100, 25 + 5 × streak)` |
| Referral | 100 to the inviter |

Level curve: `xpForLevel(n) = 60(n−1)² + 40(n−1)` — level 2 at 100 XP, 5 at 1,120, 10 at 5,220,
20 at 22,420, 41 at 97,600. No cap. `levelFromXp` is the closed-form inverse with an integer
fix-up (checked exhaustively for 0 ≤ xp < 300,000). At ~1,000–1,500 XP per hour of active play
this gives level 5 in about an hour and level 20 after roughly twenty.

### Nobody loses a level

Rows from before this batch have no `xp`. `sanitizeState` converts them once, deterministically,
from server-stored data: `xp = xpForLevel(oldLevel) + fraction × (next − current)` where
`oldLevel = floor(totalEarned / 5000) + 1` and `fraction = (totalEarned mod 5000) / 5000`. So a
veteran at old level 5 with 60 % progress starts at exactly 1,468 XP = level 5, 60 % — the badge shows
the same number as yesterday, and new XP accrues on top. New players start at 0. The leaderboard
uses the same conversion for rows not yet loaded (`levelOfRow`). Verified on the preview database
(real rows written by the previous code).

## API

* `/api/me`, `/api/ops`, `/api/claim-daily`, legacy `/api/save` return
  `progress: { level, xp, current, needed }`.
* `/api/ops` and `/api/claim-daily` return `levelUp: { from, to } | null` for the request; each op
  result carries its `xp`.
* `/api/leaderboard` level is XP-based.
* `state.level` is derived in `deriveStats` (like `clickPower`), `state.xp` persisted in `state_json`
  — no schema change.

## Client (`public/index.html`)

* Level badge uses the server `progress` when connected, the old local formula offline (unchanged
  identity; a 1-px XP bar appears under the badge with a tooltip `current / needed`).
* `playerLevel()` (arena enemy scaling) follows the same source.
* Level-ups are announced on the sync line (`🎉 مستوى جديد: N`) and in the daily-reward alert.
* XP is display-only on the client: nothing is applied optimistically, the server value wins.
